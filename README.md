## Язык программирования

Разработанный язык представляет собой минималистичный диалект Lisp. 

### Синтаксис

Синтаксис языка в форме Бэкуса-Наура:

```ebnf
<program> ::= <form> <program> | <form>
<form> ::= <defun> | <defvar> | <definterrupt> | <expression>

<defun> ::= "(" "defun" <identifier> "(" <arg-list> ")" <expression-list> ")"
<defvar> ::= "(" "defvar" <identifier> <expression> ")"
<definterrupt> ::= "(" "definterrupt" <integer> <expression-list> ")"

<arg-list> ::= <identifier> <arg-list> | <empty>
<expression-list> ::= <expression> <expression-list> | <expression>

<expression> ::= <integer>
               | <string>
               | <identifier>
               | <function-call>
               | <if-expr>
               | <setq-expr>
               | <loop-expr>
               | <print-expr>
               | <progn-expr>
               | <math-expr>

<function-call> ::= "(" <identifier> <expr-list> ")"
<expr-list> ::= <expression> <expr-list> | <empty>

<if-expr> ::= "(" "if" <expression> <expression> <expression> ")"
<setq-expr> ::= "(" "setq" <identifier> <expression> ")"
<loop-expr> ::= "(" "loop" <expression> <expression-list> ")"
<print-expr> ::= "(" "print" <expression> ")"
<progn-expr> ::= "(" "progn" <expression-list> ")"

<math-expr> ::= "(" <operator> <expression> <expression> ")"
<operator> ::= "+" | "-" | "*" | "/" | "=" | "<" | ">" | "mod"

<identifier> ::= [a-zA-Z_][a-zA-Z0-9_-]*
<integer> ::= [-]? [0-9]+
<string> ::= '"' [^"]* '"'
```

### Семантика

В данном диалекте реализована парадигма **«всё есть выражение»**. Любая конструкция, включая условные операторы, циклы и присваивания, при вычислении возвращает значение, которое может быть использовано как аргумент для других выражений.

**Примеры корректного кода:**

- Выражение `if` возвращает результат вычисленной ветви:
  ```lisp
  (print (if (= 1 x) "T" "F"))
  ```
- Выражение `setq` выполняет присваивание и возвращает присвоенное значение:
  ```lisp
  (setq x (if (= 1 x) 2 3))
  ```
- Использование результата `setq` на месте:
  ```lisp
  (print (setq x 13))
  ```
- Выражение `loop` возвращает результат последнего вычисленного выражения в теле цикла:
  ```lisp
  (setq x (loop (< i 10) 
                (setq i (+ i 1)) 
                (+ i 100)))
  ```
- Рекурсивное вычисление N-го числа Фибоначчи
  ```lisp
    (defun fib (n)
    (if (< n 2)
        n
        (+ (fib (- n 1))
            (fib (- n 2)))))

    (print (fib 10))
  ```
- Итеративное вычисление факториала
  ```lisp
    (defvar result 1)
    (defvar n 5)

    (print 
    (progn
        (loop (> n 0)
        (setq result (* result n))
        (setq n (- n 1)))
        result))
  ```

## Организация памяти

Архитектура памяти построена по модели **Гарвардской архитектуры**:

- память команд и память данных разделены;
- обе памяти однопортовые;
- машинное слово: `32` бита;
- адресация линейная, по машинным словам, а не по байтам.

### Регистры

Доступны два независимых банка регистров:

- `D0`-`D7` - данные и арифметика;
- `A0`-`A7` - адреса и указатели;
- `SP` - стековый указатель (`A7`);
- `FP` - кадровый указатель (`A6`);
- `PC` - счётчик команд;
- `SR` - статусный регистр с флагами `Z`, `N`, `IE`.

### Память команд

Память команд доступна только на чтение в рантайме.

- `0x0000-0x00FF` - таблица векторов прерываний;
- `0x0100+` - код программы.

### Память данных

Память данных доступна на чтение и запись.

- низкие адреса - статическая область;
- туда попадают глобальные переменные, константы и `pstr`-строки;
- `pstr` хранится как `L`, затем `L` машинных слов, по одному символу в каждом;
- высокие адреса - стек данных и возвратов.

Стек используется для:

- передачи аргументов;
- сохранения `PC` при `CALL` и прерываниях;
- хранения локальных переменных.

## Система команд

Процессор ориентирован на **CISC**-модель:

- переменная длина инструкций (от 1 до N машинных слов);
- операции могут обращаться прямо к памяти данных;
- поддерживаются операции с нефиксированным числом аргументов (групповая пересылка `MOV`, массовый `PUSH`, вычисление полинома `POLY`);
- ввод-вывод реализован через порты, а не через память.

### Режимы адресации и дескрипторы операндов

В формате `C` каждый операнд кодируется **8-битным дескриптором**. Для максимальной плотности кода применяется префиксное кодирование переменной длины внутри самого дескриптора.

Класс регистра выводится из контекста: базовые регистры при обращении к памяти всегда адресные (`A0-A7`), индексные — регистры данных (`D0-D7`).

| Префикс | Биты дескриптора | Режим | Синтаксис | Требует слово расширения? |
| :---: | --- | --- | --- | :---: |
| `11` | `11` `An[2:0]` `Dn[2:0]` | **База + Индекс** | `[An, Dn]` | Нет |
| `10` | `10` `An[2:0]` `imm[2:0]` | **База + Короткое смещение** | `[An + imm3]` | Нет (`imm3` = 0..7 слов) |
| `0000` | `0000` `Reg[2:0]` `0` | **Регистровый** | `R` (Dn/An) | Нет |
| `0001` | `0001` `000` `0` | **Непосредственный** | `#imm32` | **Да** (32 бита) |
| `0010` | `0010` `An[2:0]` `0` | **Косвенный** | `[An]` | Нет |
| `0011` | `0011` `An[2:0]` `0` | **Постинкремент** | `[An]+` | Нет |
| `0100` | `0100` `An[2:0]` `0` | **Предекремент** | `-[An]` | Нет |
| `0101` | `0101` `000` `0` | **Абсолютный** | `[imm32]` | **Да** (32 бита) |
| `0110` | `0110` `An[2:0]` `0` | **База + Длинное смещение** | `[An + imm32]` | **Да** (32 бита) |
| `0111` | `0111` `000` `0` | *(Резерв)* | - | - |

**Пример эффективности кодирования:**
- Обращение к элементу массива `[A0, D2]` занимает ровно 1 байт дескриптора (`11 000 010`) и не требует дополнительных слов.
- Чтение аргумента функции со стека `[FP + 2]` кодируется одним дескриптором (`10 110 010`, где `110` — это `FP` или `A6`) и также не требует слов расширения, значительно экономя память и такты выборки.

### Набор инструкций

Ниже `opcode` указан в шестнадцатеричном виде.

#### Загрузка и сохранение

| Мнемоника | Код | Применение | Описание |
| --- | --- | --- | --- |
| `MOV` | `0x01` | `MOV <src> <dst1> <dst2> ...` | пересылка между объектами; поддерживает массовое копирование в несколько приёмников |
| `MOVA` | `0x15` | `MOVA <src> <Adst1> ...` | пересылка в адресные регистры |
| `PUSH` | `0x0E` | `PUSH <src1> <src2> ...` | помещение значения(й) в стек (поддерживает массовое сохранение) |
| `POP` | `0x0F` | `POP <dst1> <dst2> ...` | извлечение значения(й) из стека |
| `IN` | `0x10` | `IN <port> <dst>` | чтение из порта во входной операнд |
| `OUT` | `0x11` | `OUT <src> <port>` | запись значения в порт |

#### Арифметические и логические

| Мнемоника | Код | Применение | Описание |
| --- | --- | --- | --- |
| `ADD` | `0x02` | `ADD <src> <dst>` | `dst = dst + src`, обновляет флаги `Z` и `N` |
| `SUB` | `0x03` | `SUB <src> <dst>` | `dst = dst - src`, обновляет флаги `Z` и `N` |
| `MUL` | `0x04` | `MUL <src> <dst>` | `dst = dst * src`, обновляет флаги `Z` и `N` |
| `DIV` | `0x05` | `DIV <src> <dst>` | `dst = dst / src`, обновляет флаги `Z` и `N` |
| `MOD` | `0x06` | `MOD <src> <dst>` | `dst = dst % src`, обновляет флаги `Z` и `N` |
| `CMP` | `0x07` | `CMP <lhs> <rhs>` | сравнение без сохранения результата, обновляет флаги `Z` и `N` |
| `POLY` | `0x1B` | `POLY <dst> <x> <c0> ... <cn>` | вычисляет полином $c_0 + c_1 x + c_2 x^2 + ...$ и сохраняет в `dst` |

#### Ветвление

| Мнемоника | Код | Применение | Описание |
| --- | --- | --- | --- |
| `JMP` | `0x08` | `JMP <offset>` | безусловный относительный переход |
| `BEQ` | `0x09` | `BEQ <offset>` | переход, если `Z = 1` |
| `BLT` | `0x0A` | `BLT <offset>` | переход, если `N = 1` |
| `BGT` | `0x0B` | `BGT <offset>` | переход, если `Z = 0` и `N = 0` |
| `CALL` | `0x0C` | `CALL <offset>` | вызов подпрограммы (PC-относительно) с сохранением `PC` в стек |
| `RET` | `0x0D` | `RET` | возврат из подпрограммы |
| `IRET` | `0x14` | `IRET` | возврат из прерывания с восстановлением `SR` и `PC` |

#### Остальное

| Мнемоника | Код | Применение | Описание |
| --- | --- | --- | --- |
| `EI` | `0x12` | `EI` | разрешить прерывания (`IE = 1`) |
| `DI` | `0x13` | `DI` | запретить прерывания (`IE = 0`) |

### Бинарное кодирование

Инструкция имеет переменную длину и считывается процессором по мере декодирования.
Номер регистра в дескрипторе занимает ровно **3 бита** (`0..7`).

#### Формат A. Команды без операндов
Используется для `RET`, `EI`, `DI`, `IRET`.

| Биты | Поле | Смысл |
| --- | --- | --- |
| `[31:24]` | `opcode` | код операции |
| `[23:0]` | `-` | зарезервировано, заполняется нулями |

*Такая команда занимает ровно одно 32-битное машинное слово.*

#### Формат B. Ветвления и вызовы (PC-Relative)
Используется для `JMP`, `BEQ`, `BLT`, `BGT`, `CALL`. Смещение кодируется непосредственно в команде, исключая необходимость в дескрипторах операндов.

| Биты | Поле | Смысл |
| --- | --- | --- |
| `[31:24]` | `opcode` | код операции |
| `[23:0]` | `offset` | 24-битное знаковое смещение относительно текущего `PC` |

*Размер: 1 машинное слово. Обеспечивает относительные переходы в огромном диапазоне.*

#### Формат C. Общий формат (CISC переменной длины)
Используется для команд с переменным числом операндов (`MOV`, `PUSH`, `POLY`, арифметики). Позволяет упаковать информацию об операндах максимально плотно.

Каждый операнд кодируется **8-битным дескриптором** по таблице выше.

##### Слово 1: Заголовок команды
В первое слово помещается опкод, счётчик операндов и сразу до двух дескрипторов. Если у команды 1 или 2 операнда (как у 90% инструкций), она полностью помещается в это слово.

| Биты | Поле | Смысл |
| --- | --- | --- |
| `[31:24]` | `opcode` | код операции |
| `[23:16]` | `operand count` ($N$) | количество операндов (от 1 до 255) |
| `[15:8]` | `desc 1` | дескриптор 1-го операнда (если $N \ge 1$) |
| `[7:0]` | `desc 2` | дескриптор 2-го операнда (если $N \ge 2$) |

##### Слова 2..K: Дополнительные дескрипторы (только если $N > 2$)
Если команда принимает больше 2-х операндов (например, массовый `PUSH` или `POLY`), процессор считывает следующие машинные слова. В каждое 32-битное слово помещается ровно 4 дополнительных дескриптора (по 8 бит).

##### Слова расширения: 32-битные константы / адреса
После декодирования всех дескрипторов процессор определяет, каким операндам требуются полные 32-битные значения (режимы `0001: #imm32`, `0101: [imm32]`, `0110: [An+imm32]`).
Для каждого такого операнда из памяти команд читается **ровно одно полное 32-битное слово расширения** (в том порядке, в котором шли операнды).

*Пример для инструкции `ADD D1, D2` (2 операнда, без констант):*
Занимает ровно 1 машинное слово.

*Примеры плотного кодирования:*
- `MOV [A0, D2], D0` использует один дескриптор для первого операнда (`11 000 010`) и не требует слова расширения.
- `MOV [FP + 2], D0` использует один дескриптор для первого операнда (`10 110 010`, где `FP` соответствует `A6`) и также не требует слова расширения.

### Прерывания

Механизм `trap` работает так:

1. при активном `IE` прерывание останавливает выборку;
2. `PC` и `SR` сохраняются в стек;
3. `IE` сбрасывается;
4. `PC` загружается из таблицы векторов;
5. обработчик выполняет ввод-вывод и завершается `IRET`.
