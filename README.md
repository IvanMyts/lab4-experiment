## Язык программирования

Разработанный язык представляет собой минималистичный диалект Lisp. 

### Синтаксис

Синтаксис языка в форме Бэкуса-Наура:

```ebnf
<program> ::= <form> <program> | <form>
<form> ::= <defun> | <defvar> | <definterrupt> | <expression>

<defun> ::= "(" "defun" <identifier> "(" <arg-list> ")" <expression-list> ")"
<defvar> ::= "(" "defvar" <identifier> <expression> ")"
<definterrupt> ::= "(" "definterrupt" <integer> <expression-list> ")"

<arg-list> ::= <identifier> <arg-list> | <empty>
<expression-list> ::= <expression> <expression-list> | <expression>

<expression> ::= <integer>
               | <string>
               | <identifier>
               | <function-call>
               | <if-expr>
               | <setq-expr>
               | <loop-expr>
               | <print-expr>
               | <progn-expr>
               | <math-expr>

<function-call> ::= "(" <identifier> <expr-list> ")"
<expr-list> ::= <expression> <expr-list> | <empty>

<if-expr> ::= "(" "if" <expression> <expression> <expression> ")"
<setq-expr> ::= "(" "setq" <identifier> <expression> ")"
<loop-expr> ::= "(" "loop" <expression> <expression-list> ")"
<print-expr> ::= "(" "print" <expression> ")"
<progn-expr> ::= "(" "progn" <expression-list> ")"

<math-expr> ::= "(" <operator> <expression> <expression> ")"
<operator> ::= "+" | "-" | "*" | "/" | "=" | "<" | ">" | "mod"

<identifier> ::= [a-zA-Z_][a-zA-Z0-9_-]*
<integer> ::= [-]? [0-9]+
<string> ::= '"' [^"]* '"'
```

### Семантика

В данном диалекте реализована парадигма **«всё есть выражение»**. Любая конструкция, включая условные операторы, циклы и присваивания, при вычислении возвращает значение, которое может быть использовано как аргумент для других выражений.

**Примеры корректного кода:**

- Выражение `if` возвращает результат вычисленной ветви:
  ```lisp
  (print (if (= 1 x) "T" "F"))
  ```
- Выражение `setq` выполняет присваивание и возвращает присвоенное значение:
  ```lisp
  (setq x (if (= 1 x) 2 3))
  ```
- Использование результата `setq` на месте:
  ```lisp
  (print (setq x 13))
  ```
- Выражение `loop` возвращает результат последнего вычисленного выражения в теле цикла:
  ```lisp
  (setq x (loop (< i 10) 
                (setq i (+ i 1)) 
                (+ i 100)))
  ```
- Рекурсивное вычисление N-го числа Фибоначчи
  ```lisp
    (defun fib (n)
    (if (< n 2)
        n
        (+ (fib (- n 1))
            (fib (- n 2)))))

    (print (fib 10))
  ```
- Итеративное вычисление факториала
  ```lisp
    (defvar result 1)
    (defvar n 5)

    (print 
    (progn
        (loop (> n 0)
        (setq result (* result n))
        (setq n (- n 1)))
        result))
  ```
#### Стратегия вычислений

Eager (applicative order), слева направо: в форме `(f a b c)` сначала вычисляются `a`, `b`, `c` именно в указанном порядке, потом вызывается `f`. Ленивости и макросов нет. Специальные формы (`if`, `loop`, `setq`, `progn`, `defun`, `defvar`, `definterrupt`) обрабатываются транслятором отдельно — у них собственные правила вычисления аргументов; всё остальное — это обычный вызов функции с предварительным вычислением всех аргументов.

#### Типы и литералы

Типизация динамическая. Поддерживается два типа значений:

- **Integer** — 32-битное знаковое число. Литералы: `42`, `-7`, `0`. Арифметика (`+`, `-`, `*`, `/`, `mod`) и сравнения (`<`, `>`, `=`) определены только для целых.
- **String** — неизменяемая строка. Литералы: `"hello"`. Допустимые операции: передача в `print` и сравнение на равенство через `=`. Физически хранится в data-memory как `pstr` — слово длины, затем `L` машинных слов по одному символу.

Истинность в `if` и `loop`: `0` — ложь, любое другое целое — истина. Сравнения возвращают `1` (истина) или `0` (ложь). Проверка типов при трансляции не выполняется — за корректность отвечает программист.

#### Области видимости

Лексические, ровно два уровня — глобальный и текущий вызов функции:

- `defvar x e` создаёт глобальную переменную `x` со значением `e`. Глобалы видны отовсюду.
- Параметры `defun` — локальные на время вызова, перекрывают глобал того же имени.
- `setq x e` присваивает значение **уже существующей** переменной: сначала ищется локальная, потом глобальная. Если `x` нигде не объявлена — ошибка трансляции.
- Вложенных `defun`, анонимных функций и замыканий нет.
- Рекурсия (включая взаимную) разрешена: имя, объявленное через `defun`, видно сразу после объявления, в том числе в собственном теле.

#### Возвращаемые значения

Реализована классическая парадигма «всё есть выражение»: любая форма что-то возвращает, и результат можно передать дальше.

| Форма | Возвращает |
| --- | --- |
| `defvar` / `defun` / `definterrupt` | `0` (используются ради побочного эффекта) |
| `setq x e` | значение `e` |
| `if p t e` | значение взятой ветви |
| `loop p body...` | значение последнего выражения тела на последней итерации; `0`, если тело не выполнилось ни разу |
| `progn e1 ... en` | значение `en` |
| `print e` | значение `e` |
| `(f a1 ... an)` | то, что вернула функция `f` (последнее выражение её тела) |

#### Прерывания

`(definterrupt N body...)` регистрирует тело как обработчик прерывания с вектором `N`. Тело компилируется как отдельная процедура, её адрес записывается в ячейку `N` таблицы векторов в памяти данных. При наступлении прерывания процессор сохраняет `PC` и `SR` на стек, гасит флаг `IE`, передаёт управление по адресу из таблицы. В конце тела транслятор автоматически вставляет `IRET`, который восстанавливает `PC` и `SR` (а вместе с `SR` — и `IE`). Для общения с портами внутри обработчика используются инструкции `IN` и `OUT` (см. раздел «Система команд»).

#### Отображение выражений на регистры и память

Стратегия размещения транслятором максимально прямолинейная:

- **Целочисленный литерал** вкладывается в инструкцию как непосредственный операнд. Если значение укладывается в диапазон −128..127, транслятор устанавливает бит `S=1` в дескрипторе и помещает значение в поле `imm8` — слово расширения не требуется. Иначе используется полный `#imm32` со словом расширения.
- **Строковый литерал** один раз помещается в data-memory как `pstr` (длина + символы). Транслятор генерирует встроенную подпрограмму `__print_str`, которая использует режим автоинкремента `[Rn]+` для эффективного посимвольного вывода строки без раздувания кода.
- **Глобальная переменная** (`defvar`) — именованная ячейка в data-memory; доступ через абсолютный режим `[imm32]`.
- **Параметр функции** размещается на стеке. Доступ через смещение от `FP`: `[FP + imm]`. Для функций с числом параметров до ~60 смещение укладывается в `imm8` (бит `S=1`), и доступ кодируется одним словом без расширения. Кадр строится как `[saved FP, return PC, argN, ..., arg1]`.
- **Промежуточные результаты вычисления выражений** вычисляются через стек и регистры `R0`-`R5`. Левое подвыражение вычисляется в `R0` и сохраняется на стек `PUSH R0`. Правое вычисляется в `R0`. Затем выполняется операция с использованием режима постинкремента: `ADD R0, [SP]+`. Это позволяет снять аргумент со стека и выполнить арифметику за одну инструкцию, избегая лишних `POP`.
- **Логические выражения** (`<`, `>`, `=`) не используют ветвлений. Для материализации логического значения транслятор использует инструкции условного присваивания (`SETL`, `SETG`, `SETE`), которые записывают `1` (истина) или `0` (ложь) напрямую в регистр `R0`.
- **Возвращаемое значение функции** всегда передаётся в `R0`.

## Организация памяти

Архитектура памяти построена по модели **Гарвардской архитектуры**:

- память команд и память данных разделены;
- обе памяти однопортовые;
- машинное слово: `32` бита;
- адресация линейная, по машинным словам, а не по байтам.

### Регистры

Доступны два независимых банка регистров:

- `R0`-`R5` — рабочие регистры (используются транслятором);
- `R6`-`R13` — зарезервированы для будущих расширений;
- `R14` (`FP`) — кадровый указатель;
- `R15` (`SP`) — стековый указатель;
- `PC` — счётчик команд;
- `SR` — статусный регистр с флагами `Z`, `N`, `IE`.

### Память команд

Память команд доступна только на чтение в рантайме.

- `0x0000+` - код программы.

Таблица векторов прерываний хранится не здесь, а в памяти данных (см. ниже).

### Память данных

Память данных доступна на чтение и запись.

- `0x0000-0x00FF` - таблица векторов прерываний (IVT): в ячейке `N` лежит адрес обработчика вектора `N` в памяти команд;
- далее - статическая область: глобальные переменные, константы и `pstr`-строки;
- `pstr` хранится как `L`, затем `L` машинных слов, по одному символу в каждом;
- высокие адреса - стек данных и возвратов.

Стек используется для:

- передачи аргументов;
- сохранения `PC` при `CALL` и прерываниях;
- хранения локальных переменных.

## Система команд

Процессор ориентирован на **CISC**-модель:

- переменная длина инструкций (от 1 до N машинных слов);
- операции могут обращаться прямо к памяти данных;
- поддерживаются операции с нефиксированным числом операндов (`PUSHM`, `POPM`);
- ввод-вывод реализован через порты.

### Режимы адресации и дескрипторы операндов

В двухоперандных инструкциях (формат `C2`) каждый операнд кодируется строго **8-битным дескриптором**. Это позволяет конвейеру (Instruction Decode) за один такт определять длину инструкции.

Формат дескриптора: `[Режим: 3 бита] [Регистр: 4 бита] [S: 1 бит]`.

Поле `Регистр` адресует все 16 регистров единого банка `R0`-`R15` (4 бита, значения `0..15`). Это согласовано с форматом C1, где регистры тоже кодируются 4 битами.

Бит **S (Short)** управляет источником значения операнда. Если `S=0`, режимы `001`/`010`/`011` читают полное 32-битное слово расширения как обычно. Если `S=1`, вместо слова расширения используется поле `imm8` из младшего байта `[7:0]` слова инструкции (знакорасширяется до 32 бит). Положение `imm8` в `[7:0]` **фиксировано для всех форматов** (и C2, и C3) и не зависит от того, какому дескриптору принадлежит короткое значение. Только один из двух операндов может иметь `S=1`, так как поле `imm8` в инструкции одно.

| Режим (bin) | Мнемоника | Синтаксис | S=0 | S=1 | Назначение |
| :---------: | --- | --- | :-: | :-: | --- |
| `000` | **Регистровый** | `Rn` | — | — | Работа с промежуточными данными и указателями |
| `001` | **Непосредственный** | `#imm` | слово расширения (imm32) | `imm8` из `[7:0]` | Целочисленные литералы |
| `010` | **Абсолютный** | `[imm]` | слово расширения (imm32) | `imm8` из `[7:0]` | Доступ к глобальным переменным (`defvar`) |
| `011` | **База + Смещение** | `[Rn + imm]` | слово расширения (imm32) | `imm8` из `[7:0]` | Доступ к аргументам (`[FP + offset]`) |
| `100` | **Постинкремент** | `[Rn]+` | — | — | Чтение со стека (`[SP]+`) и перебор строк |
| `101` | **Регистровый косвенный** | `[Rn]` | — | — | Обращение по указателю без смещения (адрес = `Rn`) |

Это позволяет кодировать часто встречающиеся паттерны без слова расширения: `ADD R0, #1` (маленькая константа, диапазон −128..127), `MOV R0, [FP+2]` (доступ к аргументу с малым смещением) — каждая такая инструкция занимает ровно 1 машинное слово вместо 2.

Режим `[Rn]` (косвенный без смещения) не использует ни `imm8`, ни слово расширения, поэтому не занимает единственный короткий слот `S=1` — его можно сочетать с коротким непосредственным операндом у второго дескриптора (например, `ADD [Rn], #5` укладывается в одно слово). Без отдельного режима тот же доступ пришлось бы кодировать как `[Rn+0]`, отнимая `S=1`-слот у второго операнда.

Оптимизация конвейера: из архитектуры исключены режимы с предекрементом и сложной индексной арифметикой, так как они вызывают структурные конфликты (Data Hazards) в ALU.

### Таблица кодов операций (Opcode Map)

Пространство кодов разделено на четыре группы:

#### Группа 1: Переменное число операндов (сохранение контекста)

Используются для группового сохранения/восстановления регистров (в первую очередь в обработчиках прерываний). Принимают только регистры, поэтому их длина легко предсказуема декодером.

| Мнемоника | Код | Формат | Описание |
| --- | --- | --- | --- |
| `PUSHM` | `0x11` | `C1` | `PUSHM count, R1...Rn`. ControlUnit в цикле: для каждого регистра декрементирует `SP` и записывает значение в `D-Mem[SP]` (`N` тактов). |
| `POPM` | `0x12` | `C1` | `POPM count, R1...Rn`. ControlUnit в цикле: для каждого регистра читает `D-Mem[SP]` и инкрементирует `SP` (`N` тактов). |

**Вызов функции (без INVOKE).** Отдельной команды вызова с передачей аргументов нет. Lisp-вызов транслятор разворачивает в передачу аргументов через стек (`PUSHM` или последовательность `PUSH`) и затем `CALL func`. Это чуть длиннее по коду, но упрощает аппаратуру (нет многотактного состояния передачи аргументов и абсолютного перехода по слову расширения).

**Пролог и эпилог функции.** Сохранение и восстановление кадра стека (`FP`) выполняется транслятором вручную. Генерируемый пролог: `PUSH FP` / `MOV FP, SP`. Эпилог: `MOV SP, FP` / `POP FP` / `RET`.

**`CALL`** (группа 3) — простой переход с сохранением `PC`, без передачи аргументов; используется транслятором как для пользовательских функций (аргументы заранее уложены на стек), так и для внутренних подпрограмм (`__print_str` и подобных).

#### Группа 2: Фиксированное число операндов (ALU и Пересылки)

| Мнемоника | Код | Формат | Описание |
| --- | --- | --- | --- |
| `MOV` | `0x20` | `C2` | `dst = src` (Копирование данных или адресов) |
| `ADD` | `0x21` | `C2` | `dst = dst + src` |
| `SUB` | `0x22` | `C2` | `dst = dst - src` |
| `MUL` | `0x23` | `C2` | `dst = dst * src` |
| `DIV` | `0x24` | `C2` | `dst = dst / src` |
| `MOD` | `0x25` | `C2` | `dst = dst % src` |
| `CMP` | `0x26` | `C2` | Сравнение, установка флагов `Z`, `N` |
| `IN` | `0x27` | `C2` | `IN port, dst` |
| `OUT` | `0x28` | `C2` | `OUT src, port` |
| `SETL` | `0x29` | `C3` | `dst = (N == 1) ? 1 : 0` (Set if Less) |
| `SETG` | `0x2A` | `C3` | `dst = (Z == 0 && N == 0) ? 1 : 0` (Set if Greater) |
| `SETE` | `0x2B` | `C3` | `dst = (Z == 1) ? 1 : 0` (Set if Equal) |

#### Группа 3: Ветвления

Ветвления используют 24-битное знаковое смещение относительно адреса следующей команды.

| Мнемоника | Код | Формат | Описание |
| --- | --- | --- | --- |
| `JMP` | `0x30` | `B` | Безусловный переход |
| `BEQ` | `0x31` | `B` | Переход, если `Z = 1` |
| `BNE` | `0x32` | `B` | Переход, если `Z = 0` (Not Equal, ложь в Lisp) |
| `BLT` | `0x33` | `B` | Переход, если `N = 1` |
| `BGT` | `0x34` | `B` | Переход, если `Z = 0` и `N = 0` |
| `CALL` | `0x35` | `B` | Вызов функции (без параметров) |

#### Группа 4: Системные (Безоперандные)

| Мнемоника | Код | Формат | Описание |
| --- | --- | --- | --- |
| `RET` | `0x40` | `A` | Возврат из функции |
| `IRET` | `0x41` | `A` | Возврат из прерывания |
| `EI` | `0x42` | `A` | Разрешить прерывания |
| `DI` | `0x43` | `A` | Запретить прерывания |
| `HALT` | `0x44` | `A` | Остановка процессора |

### Бинарное кодирование

Инструкция считывается процессором по мере декодирования. Машинное слово — 32 бита.

#### Формат A. Безоперандные команды

| Биты | Смысл |
| --- | --- |
| `[31:24]` | Опкод операции |
| `[23:0]` | Нули |

#### Формат B. Ветвления и вызовы (PC-Relative)

| Биты | Смысл |
| --- | --- |
| `[31:24]` | Опкод операции |
| `[23:0]` | 24-битное знаковое смещение относительно адреса **следующей** команды (`PC_next`) |

#### Формат C1. Группа 1 (Переменное число операндов: PUSHM, POPM)

Операндами выступают только регистры, что избавляет конвейер от сложных вычислений адреса. В первое слово помещается до 4 регистров. Если `count > 4`, считывается следующее машинное слово с оставшимися регистрами.

| Биты | Смысл |
| --- | --- |
| `[31:24]` | Опкод (`PUSHM` или `POPM`) |
| `[23:16]` | `count` (число операндов, от `1` до `12`) |
| `[15:12]`, `[11:8]`, `[7:4]`, `[3:0]` | 4-битные идентификаторы регистров (операнды 1..4) |
| *(Слово 2)* | *(Опционально)* Идентификаторы регистров (операнды 5..12), если `count > 4` |

#### Формат C3. Однооперандные команды (SETL, SETG, SETE)

| Биты | Смысл |
| --- | --- |
| `[31:24]` | 8-битный код операции |
| `[23:16]` | 8-битный дескриптор операнда (приёмник): `[mode:3][reg:4][S:1]` |
| `[15:8]` | Резерв (`0x00`) |
| `[7:0]` | `imm8` — короткое значение (используется, если `S=1`; иначе `0x00`) |

Инструкции `SETcc` читают флаги из `SR` и записывают `1` или `0` в приёмник. Второго операнда нет — результат определяется только состоянием флагов после предшествующей `CMP`.

> **Единое положение `imm8`.** Короткое значение (`S=1`) всегда лежит в младшем байте `[7:0]`
> инструкции — независимо от формата (C2 или C3) и от того, какому дескриптору оно принадлежит.
> Это упрощает извлечение: знакорасширитель всегда берёт `IR[7:0]`, отдельный мультиплексор позиции
> не нужен.

#### Формат C2. Общий формат для группы 2 (Два операнда)

| Биты | Смысл |
| --- | --- |
| `[31:24]` | 8-битный код операции |
| `[23:16]` | 8-битный дескриптор 1-го операнда (приёмник): `[mode:3][reg:4][S:1]` |
| `[15:8]` | 8-битный дескриптор 2-го операнда (источник): `[mode:3][reg:4][S:1]` |
| `[7:0]` | `imm8` — короткое непосредственное значение (используется, если у одного из операндов `S=1`; иначе `0x00`) |

Логика декодирования:

- Если оба дескриптора имеют `S=0` — поведение классическое: режимы `001`/`010`/`011` читают 32-битное слово расширения из потока инструкций.
- Если один из дескрипторов имеет `S=1` — его значение берётся из `imm8[7:0]` (знакорасширяется до 32 бит), слово расширения для него не читается. Диапазон: −128..127.
- `S=1` допускается только у одного операнда (поле `imm8` одно). Транслятор гарантирует это статически.

### Прерывания

Механизм `trap` работает так:

1. прерывание проверяется на границе команд при активном `IE`; команды, уже находящиеся в OF/EX и MEM/WB, дотекают до конца (точное прерывание), младшие стадии сбрасываются;
2. адрес первой невыполненной команды (`PC`), а затем `SR` аппаратно сохраняются в стек;
3. `IE` сбрасывается, `PC` загружается из таблицы векторов;
4. обработчик прерывания (тело `definterrupt`), сгенерированный транслятором, начинается с инструкции `PUSHM count, R0...R5` для защиты контекста прерванной программы;
5. перед `IRET` транслятор вставляет `POPM` для восстановления сохранённых регистров; `IRET` снимает со стека `SR`, затем `PC`.
